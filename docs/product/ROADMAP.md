# 饮食记录与选择：分阶段实施与验收

最新提案：[产品方案 v0.4.0](versions/v0.4.0.md)，扩展规则待评审；拍照方向依据 [v0.3.0](versions/v0.3.0.md)。状态：均待实施；应用仍是 v0.1.0。旧的完整审批实施清单保存在 [plan/v0.2.0](https://github.com/iTuer/waitupfat/blob/plan/v0.2.0/docs/product/ROADMAP.md)，不再作为本次 MVP 的完整发布依赖。

## A 阶段：可靠记录

核心验收：一张图无误时不打字即可确认；一个标签错误可以单独修正；无网络不假报保存；重复请求不重复记录；模型迟到不覆盖用户输入；第二天找到照片与修改；他人看不到私密图片。读取失败不能显示为零条数据；删除后迟到任务不复活内容。完整场景见 v0.4.0 第七节。

试用观察：主动操作耗时、端到端等待、无键盘保存占比、纠错耗时、真实保存成功与次日回看。先确认低负担记录成立，再评审帮选与 AI 分析的下一轮范围。

## B 阶段提议：具体选择（待方向确认）

- P07：独立候选帮选、单选、截止、本人提交管理；零票、平票、并发截止与重复投票有验收。
- P08：想吃清单和实际选择回填；不自动把候选或收藏记成已吃。
- P09：公开审核、举报处置、撤回、访问隔离；旧审批保持原语义，不能将原票变成候选票。
- 用小批真实试用者验证饭点回应，不增加假票或自动邀人。若回应不足，暂缓扩大社区。

## C 阶段提议：AI 与付费价值（待条件落实）

- P10：基于已确认记录的回顾与安排，说明覆盖、来源、缺失与偏好；不以三天作为充分了解的证明。
- P11：测量每次可用识别成本、失败重试、图片成本，确定供应商、预算和权益；三次额度为实验值。
- P12：付费与数据处理条件明确并获授权后，另行实施支付、权益、退款和到期流程；目前不接收款。

评分、复杂审批、实时陪伴、营养精算、体重、PK 与小程序均延后；后续如重新排入，新增变更记录。代码实现、测试、应用版本和部署状态单独记录。
