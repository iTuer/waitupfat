# 简约布局评估 v1

日期：2026-11-03（Asia/Shanghai）。依据用户提供的线框及本地饭搭子演示。用户明确偏好低饱和、简约、较少圆角。本次为视觉提案；不覆盖原 demo 或正式产品方案，不改变应用、数据库或部署。原截图与私人导出不上传。

## 现有布局

优点：日期、时间与餐盘能把三餐放在一天的节奏中；底部“开吃”适合单手操作；中心返回当前时间有助于浏览历史后定位。线框本身的灰白方向已经比原绿色磨砂演示更克制。

问题：大餐盘占据首屏但信息稀疏；中央大白面板遮住餐盘，圆盘和面板同时争夺注意力；“99 分”容易造成精确营养判断的错觉；“开吃”需要说明是否启动计时以及结束方式；日期、周报和返回现在的操作层级需明确。中心点击返回应有可见提示，圆盘旋转需保留可点击餐次入口，避免仅靠手势。

## 两个方案

[静态对照页](../prototypes/2026-11-03-quiet-layouts.html)。包含虚构餐食与日期示例，控件仅作视觉展示，不执行记录、计时或导航。

- A：保留上部餐盘，控制其高度约占手机页面三分之一；缩短浮层，餐食名称和结构反馈直接排版。优先推荐：保留特色，同时使信息更清楚。餐盘和返回当前时间保留圆形语义，其他按钮 4px 圆角。
- B：用纵向时间轴显示早餐、午餐、晚餐，靠字体、留白、细线区分餐次。适合优先追求扫描效率的方向；代价是餐盘辨识度减弱。内容增长时实际实现应让餐次区滚动，保留底部按钮。

视觉参数：暖白 #F9F8F4、墨灰 #252823、灰橄榄 #737D61；去渐变、磨砂、明显阴影和大面积彩色背景；避免所有文字都用浅灰。操作状态必须同时用文字和边线表达，不能只靠颜色。结构反馈使用可解释的类别，未知时明确未知，不直接沿用 99 分。

验证范围：本地浏览器查看文字、层级、餐盘、主操作及窄屏布局，修正窄屏底部遮挡。未接入 AI、持久化、通知、拍照服务；实际触控、可访问性和新手手势理解仍需在交互实现后验证。用户尚未选择最终方案，可保留文件供比较，不影响现有应用。
