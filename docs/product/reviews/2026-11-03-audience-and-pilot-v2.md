# 目标人群与首轮试用方案 v2

日期：2026-11-03（Asia/Shanghai）。根据用户反馈修订 [v1](2026-11-03-audience-and-pilot-v1.md)：共用菜单依赖他人持续劳动，选餐建议也容易被通用 Agent 覆盖。本版为市场探索假设，未招募、开发或部署，不替代正式方案 v0.4.0。

## 核心待验证问题

**谁反复想改善饮食，却在日常执行中断掉？什么最小的个人闭环能帮助他继续？** 不预设食堂、外卖或特定职业是目标人群。优先寻找过去三个月至少两次尝试调整饮食、但因记录麻烦、忘记或缺少反馈而中断的成年人；访谈中也纳入能持续执行的人作为对照。

候选核心闭环：本人选一个适合自己的行为目标 → 在真实用餐时极简记录或打卡 → 看到连续执行与中断原因 → 得到下一次可做的小建议。即使没有其他用户贡献内容，个人也必须能完成这个闭环。社群仅测试能否提高持续性，不能成为基础价值的依赖。

与通用 Agent 的区别**不能靠功能清单宣称**。待验证的产品价值是用餐时的低操作成本、连续状态与可见进展、适时且可关闭的提醒，以及朋友之间自愿的陪伴。通用 Agent 也能给建议；若相同任务下它一样省事、用户一样持续回来，就没有理由独立开发这些能力。

## 两周探索与小试用

1. 从用户已有联系、本地生活／习惯养成群和相关公开讨论中寻找潜在参与者；经群主允许发布邀请。招募文案围绕“最近一次想改变饮食却没坚持下去”，不先推销 App 或挑战。约 12 次访谈记录触发时刻、中断原因、现有工具、是否愿意打卡及对公开分享的顾虑。
2. 邀请约 6–8 人试用 7 天，每人自选一个低风险、可观察的行为，如记录一餐、规律吃一顿饭或留意进食节奏。用私密表单／聊天原型即可；主持者只负责收集和按约定发送反馈，记录每人每天的人工服务分钟数。没有产品能力时明确标注人工辅助。
3. 前半程测试个人打卡闭环；后半程让愿意者自愿加入熟人小组，观察群组是否带来额外回用。不要求陌生人替别人更新菜单、投票或提供营养判断。
4. 对同一任务提供“平常做法／通用 Agent”对照，比较完成一次记录的时间、主动回用、主观负担和实际可执行性；最后问用户愿意保留哪一项以及为什么。不能把主持者的高频提醒误算成产品留存。

探索性继续条件：至少 6/12 位受访者能描述最近发生的重复困难；至少 4/8 位试用者在第 5–7 天无需主持者催促仍完成目标；至少 3 位能具体说出相较现有方法或通用 Agent 的额外价值。数字仅为小样本决策门槛，不证明市场规模、健康效果或付费意愿。逐人记录退出和中断原因、人工服务成本。

## 能力取舍

首轮只做自选目标、极简记录、可见进展和一次具体的下一步反馈。现有 Web v0.1.0 不具备这里设想的完整闭环；可以作为已有能力参考，不把试用原型说成已上线。拍照识别、AI 次日饮食规划、营养分析、菜单和食材管理、原生 App、灵动岛提醒、慢吃进度条、付费建群都留在候选池，依据观察决定顺序。

“每天一个鸡蛋”“每天 8 杯水”不作为所有人的统一任务。挑战应允许跳过、调整或退出，不以连续天数惩罚用户；涉及疾病、饮食限制或特殊需求时不提供个体医疗建议。一般饮食原则可参考[中国居民膳食指南核心推荐](https://wjw.fj.gov.cn/ztzl/jkjy/jkzgxd/202206/t20220615_5930367.htm)和 [WHO 健康饮食说明](https://www.who.int/news-room/fact-sheets/detail/healthy-diet)。

若个人闭环无明显价值，先换问题或人群；若个人有效而社群无增益，暂缓群组；若只有人工主持时有效，先核算服务模式，不能当作可扩展的 App 证据。正式改变产品规则时另建方案版本和决策记录。
