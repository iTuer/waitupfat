# ADR-002：拍照优先，用户纠错

- 日期：2026-10-27（Asia/Shanghai）
- 状态：采用为下一版 MVP 的产品方向；尚未实施。
- 来源：用户指出手动记录过多，并明确提出先拍照、不准再调整。

## 决定

“拍照／选图 → 自动识别餐食 → 用户按需纠错 → 确认保存”成为主流程。一句话和常吃复用是辅助入口；表单退到详情。默认当前时间、建议餐次、私密保存；份量和营养数值不是保存前置条件。

识别失败允许先保存照片，明确待补充状态。照片上传本身不等于真实识别已实现。照片需要持久存储、身份校验和与模型处理相符的数据告知；不承诺未核实的免费成本或准确率。

三餐计划、评分、复杂成就与审批结算不再是拍照 MVP 的发布依赖。额外审批作为可选支线，用户正常记录不需要等别人投票。既有线上规则在实际修改前仍然有效。

## 原因与影响

MVP 同时要减少功能范围和用户操作负担。原多字段流程把结构化工作交给用户，无法验证“低负担记录”的价值。新方向把整理工作交给系统，把用户操作集中在确认和纠错。

需要新增图片存储、识别和编辑能力；供应商、成本与权限待实现前落实。旧账号与文字记录保留，采用增量迁移。现有 [ADR-001](001-meal-recording-and-extra-approval.md) 的三餐／额外分离原则继续有效，审批参数的实施优先级由本决策调整。
