# ADR-003：围绕饮食记录与具体选择组织产品

- 日期：2026-10-28（Asia/Shanghai）。
- 状态：提出，待产品评审；没有替换线上规则。
- 依据：用户最新草稿明确“社区仅作决策”，AI 用于快捷记录、分析并安排；本次授权结合前三部分评估优化补全。

## 提议

1. 延续 ADR-002 的拍照优先主流程。基础保存、纠错和历史不依赖社区回应或购买会员。
2. 新社交流程建议改为具体候选的“帮选”，替代“允许／不允许”；旧审批保留原语义，不转换旧票。相对 ADR-001 的变更只在确认并实施后生效。
3. 记录、发布、识别分开状态；正常个人餐照保存不以公开审核通过为条件。已吃、计划与想吃分开。
4. 基础记录、有限 AI 体验、付费回顾与安排分层。每日三次等是实验参数，正式费用与供应商另行授权。
5. 营养估算作为可选扩展；区间不强行收窄、未知不当作零，多人餐不能直接平均为本人摄入。

## 理由与取舍

仅增加图片入口不足以减少负担；拍照后的必填项目也必须减少。社区应围绕明确、能迅速回应的问题，避免尚未验证需求就增加群组、PK 和内容流。AI 需要参考确认后的记录，并说明信息不足，而不是以三天作为充分了解用户的保证。

帮选可能降低冲突，也可能削弱原审批的趣味与传播；不能只凭推理宣布更优，应在小规模试用中观察实际回应与提问者反馈。会员后置会延后收入，但能先验证服务质量和成本。
